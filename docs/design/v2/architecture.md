## 〇、11-05 实测（定架构用的事实）

| 事 | 结果 | 怎么测的 |

## 一、总图：三层 + 两个进程

```
┌────────────────────────── 流息桌面应用（Electron） ──────────────────────────┐
│ 页面（renderer）：左栏 B · 库架 · 和主 Agent 聊 · 库页五标签 · 设置            │
│        │ 只经「桥」（preload，方法表三处一致，v1.0 的规矩）                      │
│ 主进程（main）：库登记 · 定时与排队 · 主 Agent 对话 · 提议卡 · 建议卡 · 桥服务    │
│        │ 调用                                                                │
│ 核心（core，纯 Node 零依赖，自己的测试）：库 · 抓取 · 流水线 · 核验 · 问库 ·     │
│        连接 · 【新】agent · 【新】proposals · 【新】suggest · 【新】registry     │
│        │ 子进程 / HTTPS                                                       │
│ 连接：连接你电脑上的 Claude Code / Codex（命令行子进程）· API key（HTTPS）        │
└──────────────────────────────────────────────────────────────────────────────┘
磁盘：<应用数据>\Streams\（设置、主 Agent 的对话与工作区、各库登记）  +  每个库自己的文件夹（v1.0 的格式，加几样）
```

三层分工（设计稿第二节，不变）：

| 层 | 在代码里是什么 | 模型调用方式 | 能动什么 |
|---|---|---|---|
| 主 Agent | `core/src/agent/`：一个长对话；对话记录流息自己存一份（正本），命令行会话 id 只是加速用的缓存 | 每一轮：流息把「当前局面摘要」+ 你这句话交给模型，要求按 JSON 格式回：`{ reply, ask?, proposals[], lookups[] }`；`lookups` 是它想看的东西（某库的概况、某来源的抓取记录），代码查好再喂回去，最多 3 次 | **只能出提议卡**（`proposals`），由代码校验、等你确认、再由代码执行；没有 shell，不能读写任意文件；它的「工作区」= 流息给它存的笔记（`agent/notes.jsonl`，也经代码写） |
| 库 Agent | v1.0 流水线里的那些调用（brief.md 曾写「每轮新开或分叉会话」，这里定为不留会话，以本文为准）：两道关打分、摘要、核验，按库的「要求」组织提示词 | 每条 / 每批一次「不能动手」的调用（v1.0 原样），**不留会话**（读的是网上内容，不让它记事也不让它动手） | 只交结构化结果；代码写账本 |
| 问库 | v1.0 `core/src/ask/` + 新的「分流」一步 | 不能动手（见下）、不留会话 | 只答；判成「改动要求」的转给主 Agent |
| 流息的代码 | 抓取、去重、账本、写盘、定时、试抓、执行已确认的提议、规则型建议 | 不调模型 | 全部写盘都在这里 |

**「不能动手」是什么意思**（本文通用说法，CLAUDE.md「零工具或只读沙箱」）：Claude Code 用 `--tools ""` 等参数，一个工具都没有；Codex 没有完全关掉工具的参数，用只读沙箱（不能写盘、默认不联网）+ 空的工作目录；API 连接本来没有工具。三者都不能改你电脑上的任何东西。

**为什么主 Agent 用「JSON 动作」而不是让命令行自己调工具**：三种连接（Claude Code、Codex、API key）用同一套办法；命令行照旧「不能动手」（v1.0 的安全约定不破）；动作是数据，代码逐条校验、能测、能重放。代价：主 Agent 想看东西要绕一次 `lookups`（最多 3 次，超了就照现有信息答）。

### 2.2 新写

| 模块 | 放哪 | 做什么 | 要点 |
|---|---|---|---|
| 库登记 `registry` | `core/src/registry/` + 主进程 | 应用知道有哪些库（id、文件夹、显示名、图标、颜色、排序），不再「一次只开一个」 | 登记表在 `<应用数据>\Streams\libraries.json`；库文件夹仍是自包含的（换电脑拷文件夹再「添加已有库」即可） |
| 定时与排队 `scheduler` | 主进程（用 v1.0 的 `nextRunAt / lastDueAt / missedRun`） | 每个库按自己的时间跑；错过的补一轮不叠加（v1.0 规则）；**同一时间只跑一轮**（一个队列，按到点先后），避免几个库同时打满连接。**v2 包 L（维护者 11-10，反馈 #1）**：别的库在跑或在排时，你点「开始」（页面或托盘）= 这个库**排到队尾**并说清排第几位、前面是谁在跑什么，不再被拒；已在跑 / 已在排的不重复排。**重设计 R1（维护者 11-11 第 6 题）**：点「立即运行」（库页头或托盘）不弹对话框——没有在跑的马上开始，别的库在跑或在排就排到队尾；按钮本身就是状态（立即运行 / 运行中 · 停止 / 排队中 · 第 n 位）；排队只在三处显示：库页头的按钮、左栏库行的小字、右栏「进度」（明细只在这里）；跑一轮对话框、概览横幅、「已排上」已删（`docs/desktop.md` §4.13） | 用量：每轮上限按库算；设置页显示全部库本月用量合计（维护者 11-05 定） |
| 主 Agent `agent` | `core/src/agent/` | 对话记录（`agent/transcript.jsonl`，正本）、局面摘要（所有库的名字 / 要求 / 待看数 / 问题 / 待定的提议）、一轮对话（发 → 收 JSON → 校验 → lookups 循环 → 落盘）、长对话压缩（超过阈值时让模型把旧对话缩成摘要，原文仍留在 jsonl） | 一次只问你一个问题（`ask` 字段只能一个，带快捷回答）；JSON 不合格式重试一次，再不行就只显示 `reply` 文本、不出卡。**包 C 实做（11-05）与上面的差别**：回的 JSON 还可以带 `note`（主 Agent 的笔记，由代码写进 `agent/notes.jsonl`，局面摘要带最近 5 条）；带 `lookups` 的回答是中间回答（别的字段不用），查询五种：`library` · `source_log` · `proposals` · `suggestions` · `notes_search`（只给已收藏条目的标题与日期）；第 3 轮查询之后那次调用不许再查，再要就算不合格（重试一次，再要就收尾）；坏回答两次之后**也不查、不记笔记**；会话缓存 `agent/session.json` 丢了、坏了或 resume 报「找不到会话」→ 开新会话、用「最新摘要 + 最近 6 轮」重建；压缩阈值 40000 字、摘要 ≤ 2000 字（不留会话的一次调用），压缩后放掉命令行会话、下一轮开新的（不让命令行那边的上下文无限长）；主 Agent 的用量记 `agent/usage.jsonl`，设置的合计里单列；Claude Code / Codex 给主 Agent 跑的空文件夹是系统临时目录下的 `%TEMP%\streams-agent-cwd`（每次调用前确认是空的；契约写的 `agent\cwd\` 实做改为临时目录，理由：保持 layout 的受保护目录约定，玄翎 11-09）。细节：`docs/core-api.md` 5.15、`docs/desktop.md` §4.6 |
| 提议卡 `proposals` | `core/src/proposals/` | 卡的种类：建库、加来源、删 / 暂停来源、改主题与关键词、改要求、改过关线、改定时 / 上限、开跑一轮；每张卡：改什么、为什么、改前 / 改后、试抓结果（加来源时代码先试抓一次） | 状态：待定 → 确认 / 不要 / 改一下（改一下 = 把你的话带回主 Agent 重出一张）；**只有「确认」由代码执行**；每张卡和结果记进 `proposals.jsonl`（全局一份 + 相关库里一份）；执行后在库的配置旁记「主 Agent 提的 · 你确认的 · 日期」。**包 B 实做（11-05）与上面的差别**：十种 `kind`（定时与上限分成 `edit_schedule` / `edit_cap` 两种）；状态多两种：`stale`（出卡后相关配置变了，确认被拒、要重出）、`failed`（生效时出错，回滚或写明到哪一步）；建库卡也先试抓每个来源，被拒 / 地址有问题的默认不勾；改前 / 改后由代码在副本上真跑一遍算出，不信出卡方；「配置旁的记录」落在库的 `_pipeline\changes.jsonl`（每次改动一行：`agent-confirmed` 带卡的 id，你在界面上直接改的记 `you`），`getWhoDecided` 读它；出卡的 `createProposal` 只在主进程、不上桥。细节：`docs/core-api.md` 5.13、`docs/desktop.md` §4.5 |
| 建议卡 `suggest` | `core/src/suggest/` | **规则型**、不花模型：来源连续 N 轮被拒 / 失败、连续三轮没有产出（v1.0 已有的数）、来源出现过写给 AI 的指令、两个库的主题关键词高度重合 | 维护者 11-05 定「先不放权」：建议卡一律要你点，没有「以后这类直接做」按钮（设计稿 UC2 第 4 步那个按钮去掉）；主 Agent 可以把建议卡变成提议卡（例如替你挑一个替代来源并试抓） |
| 对话分流 `route` | `core/src/ask/route.mjs` | 库内对话框一句话 → 提问 / 改动要求 / 拿不准 | 改动要求连同库 id 交给主 Agent，提议卡回到同一个对话框里显示 |
| 阅读模式 | 主进程 + 页面 | 「打开原文」在流息里打开原网页，可切到阅读模式（抽正文） | 原网页放在隔离的 webview 里（不给 Node、不给桥）；抽正文用 `mozilla/readability`（Apache-2.0，调研已核许可证）；抽不出就退回原网页。**包 H 实做（11-09）与上面的差别**：不用 `<webview>`（应用页面的 CSP 不许框架、`webviewTag` 关着），改为单独的**阅读窗口**（`BrowserWindow` + 一个 `WebContentsView`，`src/main/reader.mjs`）：没有 preload / 桥 / Node、`sandbox`、自己的内存分区 `streams-reader`、不许新窗口与下载、只许 http(s)、页面里的链接交系统浏览器；默认打开**阅读模式**（契约 H2：抽得出就先显示阅读页，顶上可切「原网页」，在同一个窗口里加载原地址）；抽正文 = 主进程经阅读分区取 HTML，在一个所有请求都被拒的隐藏窗口里用 `DOMParser`（不跑网页脚本、不加载任何东西）+ `@mozilla/readability` 0.6.0；不加 DOM 解析库。细节 `docs/desktop.md` §4.9 |

### 2.4 一轮怎么跑（v2）

```
定时到点（或你点「立即运行」——重设计 R1 前叫「现在跑一轮」/ 你确认了「开跑一轮」的提议卡）
  → 排队（同一时间一轮；别的库在跑时，你点的那一轮排到队尾——v2 包 L）
  → 这个库：抓取（代码）→ 去重（代码）→ 关卡①②（库 Agent 调用，提示词带 brief）
  → 摘要（库 Agent）→ 核验（规则 + 判定，含「写给 AI 的话」规则）→ 待看（代码写账本）
  → 规则型建议检查（代码）→ 有新建议就进「和主 Agent 聊」的「等你定的事」和该库的概览
  → 左栏数字刷新
```

### 2.5 权限（设计稿第二节 + 维护者 11-05 答复）

| 动作 | 谁能做 | 怎么把关 |
|---|---|---|
| 写 `notes/` | 只有你（收藏、编辑、导入写头） | `writeNoteFile` 唯一入口（V2 原样）；Agent 不经点头写 notes/：**先不能**（维护者 11-05） |
| 改库的配置（来源、主题、要求、过关线、定时、上限） | 你直接改；或主 Agent 出提议卡、你确认后由代码改 | 提议卡 schema 校验 + 只认「确认」 |
| 建库 | 你，或主 Agent 提议、你确认 | 同上；文件夹位置由你选或用默认位置（写在卡上） |
| 主动做事 | 没有人：建议卡一律要你点（**先不放权**，维护者 11-05） | — |
| 执行命令 / 读写任意文件 | 没有模型能做 | 命令行一律「不能动手」（Claude Code 零工具；Codex 只读沙箱、不联网、空工作目录）；API 连接本来就没工具 |

## 三、前端计划

**包 F 实做（11-05）与上表的差别**（详见 `docs/desktop.md` §五「界面结构」）：

**包 I 实做（11-09）与上表的差别**（详见 `docs/desktop.md` §4.10）：
