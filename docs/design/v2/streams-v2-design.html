流息 Streams v2 设计稿

2026-11-05 · 依据 维护者 本机装机反馈 #1–#11、开源调研与内容底稿 docs/design/v2/brief.md（玄翎） · 给 维护者 看

一结论

v2 是什么：流息从「一次开一个库、来源和主题靠你手动配的流水线」，变成「一个主 Agent 管着你的几个库」。左栏一直列着你所有的库和各自的待看数；跟主 Agent 聊着就能建库、改库，它要动库里的东西一律先出提议卡，你点确认才由流息的代码去改；每个库里五个标签（概览、待看、资料库、问库、来源与要求），资料直接在流息自己的阅读器里读。

和 v1.0 的差别：v1.0 一次打开一个库，换库在「设置 → 库」；左栏九个入口都属于当前那个库；没有主 Agent，模型只做打分、摘要、核验、问库这几次零工具调用；定时只跑当前打开的库。v2 把库摆上左栏、加上主 Agent 和提议卡、库内对话框自动分流问题与改动要求、定时对所有库都跑；读网上内容的库 Agent 仍然零工具，notes/ 仍然只在你点收藏或编辑时写入。

维护者 已定（11-05） 多库导航先用方案 B：左栏只放库 + 库内顶部标签，库架是左栏顶上的一个页面。方案 A 保留：库架 → 进库后左栏换成库内入口、左上返回，以后左栏要放更多功能时再换。维护者 至少三个库、会来回看。

还要你定 6 件，见 「要你定的事」：v1.0 怎么办；Agent 能不能不经你点头写进 notes/；主动建议放不放权；Claude Agent SDK 引不引入；每轮上限按库算还是全局；方案 A 什么时候换。正文里凡是碰到这几件的地方，都只写成提议或标「待你定」。

v2 还没开工，这份稿子只画设计。界面图里的库名、来源名、条目标题和数字都是示意，不是真数据。

三架构：三层分工

主 Agent 管理、沟通、派活；库的运行交给每轮新开的库 Agent；确定的活留给流息的代码。问库是每个库自己的问答会话。

层是什么读什么能做什么不能做什么
主 Agent一个长会话（经你选的连接：连接你电脑上的 Claude Code / Codex，或 API key）你说的话；各库的配置、概况、摘要（不读抓来的原文）用流息给它的工具：列库、建库提议、改来源 / 主题 / 要求的提议、开跑一轮、看各库状态、写自己的 workspace（<流息数据>/agent/：笔记、草稿）没有 shell、不能任意读写文件；改库的配置只能出提议卡，你确认后由流息的代码写
库 Agent每个库每轮新开的工作会话（或从库的基础会话分叉）这一轮抓来的条目、库的要求与主题交出结构化结果：分数和理由、摘要、核验结论零工具：不写盘、不执行、不联网；它读的是网上的内容，里面可能藏着给 AI 的指令
问库每个库自己的问答会话代码从这个库挑出的候选条目只用候选条目回答，每句带出处；识别出「改动要求」时转给主 Agent不改任何东西
流息的代码不是模型—抓取、去重、账本、写盘、定时、试抓、提议卡生效后真正去改配置—

关系图：箭头是「谁把什么交给谁」。只有流息的代码写盘；模型那几层都只交出结果或提议。

  • 为什么抓取、去重、账本留给代码：不花模型调用、能重放、能测；只有要判断的事交给模型。
  • 写盘（#11）：不是全禁，而是管「写到哪、经谁写」——写盘一律经流息自己的工具，路径和格式由代码把关；主 Agent 能写的是自己的 workspace，改库的配置要先出提议卡；读网上内容的库 Agent 不给写盘、不给执行。
  • 提议卡：主 Agent 要改任何库的东西（建库、加删来源、改主题关键词、改过关线、改要求），一律出一张卡：改什么、为什么、改前改后；按钮「确认」「改一下」「不要」。确认后由代码写，库的配置里记一笔「主 Agent 提的 · 你确认的」（接上 v1.0 首次设置里的「谁定的」记录）。样子见 P8。
  • 主动建议先记录（借 dsh-superagent）：主 Agent 自己发现的事（来源连续被拒、两个库重复追同一件事、某主题三轮没产出）只出建议卡，不自己动手。以后能不能对某一类建议放权让它自动做，待你定（第 3 件）。
  • 对话路由（#9）：库内对话框一句话进来，先判断是「问题」还是「改动要求」。问题 → 问库答；改动要求 → 转主 Agent，主 Agent 在同一个对话框里出提议卡（UC3 第 3 步）。全局对话（左栏「和主 Agent 聊」）直接是主 Agent。
  • 会话怎么延续：连接你电脑上的 Claude Code / Codex 这两种连接，命令行都有接着上次会话的办法；Codex TS SDK 有 resumeThread()，Claude Agent SDK 有 resume / forkSession。玄翎的提议是 v2 先走命令行路线（和 v1.0 一样），引不引入 Claude Agent SDK 待你定（第 4 件）。命令行的具体参数与在 Windows 上的表现 未核实，开工第一件事是实测。
  • notes/ 的规矩不变：进 notes/ 的只有你点「收藏」或编辑（v1.0 的 V2）。Agent 能不能不经你点头写进去，待你定（第 2 件）。

八要你定的事

下面 6 件都还没定，每件列出选项和玄翎的倾向。

1. v1.0 怎么办

  1. (a) 周日照原架构发 v1.0，v2 另排
  2. (b) v1.0 顺手带几处小改（#1 问库图标、#8 资料库空状态与按钮）再发
  3. (c) 推迟 v1.0，直接做 v2

玄翎倾向 (b)。

2. Agent 能不能不经你点头写进 notes/

  1. (a) 不能，只有你点收藏（现状）
  2. (b) 主 Agent 可以写，但要出提议卡
  3. (c) 某些库放权自动收藏

玄翎倾向 (a)：v2 先保持，主 Agent 用顺了再看要不要放到 (b)。

3. 主动建议放不放权

  1. (a) 主 Agent 的建议一直要你点
  2. (b) 允许你对某一类建议选「以后这类直接做」

玄翎倾向 (b)：一开始每条都要你点，「以后这类直接做」由你逐类打开（UC2 第 4 步的按钮就是它）。

4. Claude Agent SDK

  1. (a) 不引入，走命令行接续会话
  2. (b) 引入（条款是 Anthropic Commercial Terms，不是 MIT 那种开源许可证）

玄翎倾向 (a)，前提是命令行接续在 Windows 上实测可用；不可用再回来找你。

5. 定时与用量

  1. (a) 所有库都定时跑以后，每轮上限按库算
  2. (b) 全局一个总上限

玄翎倾向 (a)，另在设置里显示全部库本月用量合计。

6. 方案 A 什么时候换

  1. (a) 按左栏要放的东西多少来定（例如加了「每日简报」「跨库搜索」「主 Agent 的任务列表」放不下时）
  2. (b) 到时再说

玄翎倾向 (a)。
