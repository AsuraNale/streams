05 · 措辞规范

2026-11-11 · 依据 维护者 的补充要求：「现在这个应用里有很多措辞都太口语化了，比如“谁定的”、“改一下”、“不要”等，指代非常模糊，这些按钮和提示段落的说明需要把口语化表达改成大厂应用们的行文方式。」

这份规范管三件事：行文原则（以后新写的字照这个写）、新旧对照表（122 行，玄翎改中英两套字典时照着换）、原先写进验收标准的几处（维护者 已定，见第三节）。23 张页面稿已经全部按这份规范改过。

一、行文原则

每条后面是一组例子：前面是现在的写法，后面是改后的写法。

1. 按钮写动作本身，用动词或动宾短语，2–6 个字。 看到按钮就知道点了会发生什么、对谁发生。
不这样写：「改一下」「不要」「算了」「去掉」　这样写：「提出修改」「拒绝」「取消」「移除」
2. 指代落到对象上，不用悬空的「这个 / 这一条 / 它」。
不这样写：「用这一条」「暂停这个来源」「移除这个库」　这样写：「使用此连接」「暂停该来源」「移除该库」
3. 标题和标签用名词短语，不用问句和口头语。
不这样写：「谁定的」「这次用了什么」「为什么给你」「放在哪」　这样写：「操作来源」「本次回答依据」「推荐理由」「存储位置」
4. 状态用「已 / 未 / 待 / 中」，不用口头的进行时和否定。
不这样写：「在跑」「没过关」「等打分」「没登录」　这样写：「运行中」「未通过筛选」「待评分」「未登录」
5. 提示段落先说结果，再说下一步；不用语气词，不把程序写成人。
不这样写：「抓到的 1 条都在，没丢。」「流息没有动它们。」　这样写：「已抓取的 1 条内容已保留。」「流息尚未对其做任何修改。」
6. 人称能省则省；避不开时用「你」，不用「您」和「我」。
不这样写：「你点了才生效」「没有等你看的。」　这样写：「确认后生效」「暂无待看内容。」
7. 一个概念只用一个词，全应用统一。 见下面的「统一用词」表。
不这样写：同一件事分别叫「跑一轮 / 开始 / 试跑」　这样写：一律叫「运行」
8. 数量、时间、范围写全，单位和对象不省。
不这样写：「约 2–8 次调用」「上限 30」　这样写：「预计 2–8 次模型调用」「单次运行最多 30 次模型调用」
9. 标点克制。 省略号只用在「点了还要再填东西」的按钮上（如「更改…」「其他原因…」），不用感叹号，不用「～」。
不这样写：「设置…」「改地址…」（点了直接进入）　这样写：「配置」「修改地址」
10. 用户写的内容和模型的回答正文不改写。 库名、追踪要求、笔记正文、用户在对话里说的话保持原样；主 Agent 的回复里提到界面元素时，用界面上的词。
不这样写：主 Agent 说「我起草了一张提案卡，等你点确认」　这样写：主 Agent 说「已生成建库提议，点击「创建」后由流息创建该库」
