# 07 · 模板版：把新布局做进丽芙的模板里

2026-11-11 · 赞妮 · 第三版：**21 个画面 × 四套主题**；维护者 看完后定了四件事：应用里原有的三套主题不再保留、默认主题为研究对话、新布局与模板合成一个包（见「维护者 定的三件事」一节），以及研究对话的标题字体随应用带上（见其后一节）。

## 为什么有这一版

维护者 看了 06（我把单线黑白当成一层样式，套在照现有应用画的线框稿上）之后说：

> 这不是我期望的，我期望的不是你在现有应用的UI上修改，而是把你设计的新布局，放在这个新的UI模板里。而且之前玄翎做的老三套的那个主题和设计稿差的也很远，我不喜欢。

随后他定了：以丽芙的模板为准，四套都做（精密国际主义 / 澄明玻璃 / 研究对话 / 单线黑白），不沿用玄翎做进应用里的那三套。看完 21 个画面后，他对原有三套的决定是「不要了，只留新的」。

所以这一版反过来做：**底是丽芙的模板代码**（云织第十一轮的三套 + 第十二轮的单线黑白），我只写了一个渲染脚本，用模板自己的部件把流息新布局的内容搭进去。

## 怎么看

- 预览服务开着时：`http://localhost:8771/07-模板版/templates/单线黑白-第十二轮/index.html`（另外三套把目录名换成 `精密国际主义-第十一轮`、`澄明玻璃-第十一轮`、`研究对话-第十一轮`）。

## 用了模板的哪些部件

没有新造视觉。流息的每样东西都落在模板已有的一个部件上：

| 流息里的东西 | 模板的部件（class） |
|---|---|
| 左栏：品牌、新建库、库架、主 Agent、库列表、设置 | `brand` `navitem` `project-item` `side-footer` |
| 库页头：名字、几项概况、运行状态、「立即运行」 | `work-header` `project-heading` `header-meta` `status-chip` `btn primary` |
| 库页的四个标签 | `panel-tabs` `tab`（模板右栏的那种大标签） |
| 待看的一条、主 Agent 的提议、右栏的待确认、缺文件头的文件 | `confirmation`（模板的确认卡：标题、编号要点、底部按钮） |
| 三行要点、推荐理由、修改前后 | `decision-points` `point-index` |
| 稍后处理、未通过筛选、各库的运行、核验记录、高级设置的三段（能折叠的） | `phase-row`（模板的阶段卡） |
| 运行到哪个环节、评分环节的七个节点、校验规则 | `progress-line` `step-line` `step-dots` |
| 一次运行的数量、用量、套餐用量 | `mini-chart` `chart-row` |
| 资料库的列表、图谱的节点、严格程度三档、主题、原因快选 | `search-field` `filters` `filter` `source-card` |
| 读一篇笔记、阅读窗口、许可证正文 | `reader` `reader-paper` `readable` |
| 来源行、文件、出处、连接、示例句子 | `file-row` |
| 首次打开、新建库、来源与要求、高级设置、设置、对话框里的表单 | `new-content` `field` `form-row` `form-footer` |
| 对话（主 Agent、问库） | `thread` `user-message` `assistant-message` `speaker` `composer` `cite` |
| 库架 | `home-content` `home-toolbar` `project-tile` |
| 提示（连接出问题、缺文件头、新版本、放弃后的原因、要求已更新） | `progress-alert` |
| 编辑笔记、输入 API key、许可证与致谢、移除该库 | `dialog` `dialog-head` `dialog-body` |
| 首次打开和新建库时右栏的说明 | `home-context` |
| 空状态 | `empty-state` |

**新增的补充部件一共九个**，都以 `st-` 开头，写在 `streams/streams.css`（25 行，只管位置，不带颜色）：

| class | 为什么要加 |
|---|---|
| `st-libtabs` | 模板的主区里没有标签，库页的四个标签借了右栏的大标签，这里只给它定位置 |
| `st-split` `st-list` | 资料库要左列表、右阅读两栏（维护者 11-10 定的），模板的阅读页是整栏的；`st-list` 也用来放图谱上面那一排筛选 |
| `st-stack` | 模板里确认卡一次只出现一张，流息会连着出现几张，要留空 |
| `st-quota` | 左栏底部的套餐用量，模板这个位置放的是个人信息 |
| `st-count` | 标签上的数字（待看 2、待确认 4） |
| `st-graph` `st-node` | 模板里没有图。图谱的节点用模板的 `filter`，这两个只管把节点摆到位置上、画连线 |
| `st-window` | 阅读窗口是另开的独立窗口，没有左栏和右栏；这个 class 把三栏收成一栏，并让地址框占满剩余宽度（模板的搜索框放不下一条地址，原先在研究对话和澄明玻璃下被截断，已修） |

## 动过模板的一处

`shared/round12/line.css` 第 71 行：单线黑白下，筛选标签选中时应该翻成黑底，但这条规则被前面一条优先级更高的规则盖住了，选中和没选中看起来一样。这是我 11-10 写第十二轮时留下的错，在云织的模板里筛选标签用得少，没露出来；流息用得多（严格程度、主题、图谱的节点），就看出来了。我把选择器加了一级优先级，`UI设计\工作台\shared\round12\line.css` 同步改了同一行，两处仍然逐字节相同。**丽芙的第十一轮文件一个字没动。**

## 研究对话的标题字体：随应用带上（维护者 11-11 定，04 的第 22 题）

- 研究对话的大标题用宋体类的字（`Noto Serif SC`，没有就退到系统的 SimSun）。模板的 `shared/fonts/` 里只带了 Noto Sans SC。维护者 的电脑上系统自带 Noto Serif SC，所以稿子上看到的是它；没有这款字的电脑上，大标题会变成老式的宋体，和稿子不一样。
- 维护者 的决定是**带上**：Noto Serif SC 随应用一起携带，安装包大约多 24 MB，所有电脑上的标题都和稿子一致。
- 许可证与致谢页多一条「标题字体 · Noto Serif SC」（SIL Open Font License 1.1），模板版的「许可证与致谢」画面和线框稿 P19 已经加上。
- 这份模板版的稿子本身**没有**放进这款字的文件，仍然靠电脑上已装的那份显示；字体文件由玄翎施工时从官方发布处取。
- 澄明玻璃的标题用等线（`DengXian`，Windows 自带），不存在这个问题。

## 给玄翎的提醒

- 新布局和模板是一个包：直接在模板的样式表和部件 class 上做新布局，不要再转写成另一套 token，也不要先在旧主题上做布局。维护者 不喜欢现在应用里的三套，就是因为转写以后和设计稿差得远。
- 默认主题是研究对话；原有三套主题的实现整体移除，不留开关。
- `streams/app.js` 是演示用的渲染脚本，数据是写死的；它的价值是「哪样东西用模板的哪个部件」这张对应关系。
- 模板的 `shared/` 是从 `UI设计\工作台\shared` 原样拷的（丽芙的第十一轮包 + 我 11-10 加的第十二轮单线黑白）。
- 随包字体是两款：Noto Sans SC（模板里已有）和 Noto Serif SC（要新加）。Noto Serif SC 的字体文件和许可证文本放进应用的字体目录，按模板里 Noto Sans SC 的方式声明；研究对话的标题字体取值不用改，它本来就先找 `Noto Serif SC`。
- 内容、功能编号和措辞以 01、02、03、05 为准；外观以这一版为准；维护者 的全部决定在 04（22 题）。
