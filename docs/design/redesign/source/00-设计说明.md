## 一、一句话

流息每天要你做的只有三件事：**看新来的、存下值得的、问存下的**。别的事——调来源、改要求、看它跑得好不好——都是偶尔才做。现在的界面把「每天的」「偶尔的」和「程序内部的」平铺在同一层，所以哪儿都是按钮，哪儿都要懂。重设计只做一件事：把这三层分开。

## 二、诊断：复杂是从哪来的

维护者 说的是「功能上太复杂」。照着 21 条观察往回找，根子是四个：

**A. 一件事有好几个家。** 一张提议卡同时在 5 处（O1），排队状态在 5 处（O2），改要求有 3 个入口、改上限有 4 个（O3），右栏详情把主区的内容再放一遍（O4）。每个「家」单看都有道理，是一次次反馈叠出来的；叠在一起，用户就不知道该看哪边、信哪边——而且它们还会不同步（O5）。

**B. 流水线的内部被当成了界面。** 概览的四个数字和七行「这一轮」、关卡的七个节点和提示词编辑器、每一块旁边的「谁定的」、核验里的「判定 · 独立调用」，都是程序怎么干活，不是用户要干的活。结果是「来源与要求」一页 3.5 屏、53–65 个能点的东西（O18），用户要懂 29 个概念（O21），两个东西都叫「要求」（O8）。

**C. 同一件事有两套并行的做法。** 两种卡（提议卡 / 建议卡），处理一张建议卡要先「交给主 Agent」再去另一页处理它出的提议卡（O17）；两条建库的路，默认值不一样、步数差一倍、手动那条还漏了最关键的「写要求」（O15、O16）。

**D. 说了没做到，或者做了看不出。** 「已放进待看」待看里却没有（O12），「随时能捞回」却不能收藏（O13），「稍后」点了没变化（O11），已经记下的按钮还在（O14），进度里写的原因不对（O7），主 Agent 说的词和界面不是一套（O6），漏出原始英文报错（O9），同名按钮两种行为（O10），数字几处对不上（03 第五节）。这些单个都小，合起来让人觉得「不敢确定它到底干了什么」。

## 三、五条原则

1. **分三层。** 每天的（待看、资料库、问库）在面上；偶尔的（来源与要求）在旁边一个标签里；程序内部的（关卡、提示词、变更记录、运行记录）收进「高级设置」，功能一个不少，只是平时不用看见。
2. **一件事一个家。** 每个状态、每个动作只有一个正式的位置，别处最多放一个数字或一行小字指过去。要你点头的事只在右栏「待确认」；运行和排队的明细只在右栏「进度」；分数的理由只在右栏「详情」。
3. **一种卡，一次点头。** 「要你点头的事」只有一种卡，不管是主 Agent 提的还是流息按规则发现的；卡上直接是能点的动作，点一次就完，不用跨页。每一件仍然要你点了才动（这条硬约束不变）。
4. **两条路，一个终点。** 说一句让主 Agent 建，和自己填表建，问的是同一组问题（追什么、去哪抓、多严、什么时候跑），默认值一样，建完都直接跑第一轮、落到待看。
5. **说到做到，数字一个口径。** 点了就有看得见的变化；界面说「已……」的事当场成立；一轮只用一条漏斗讲清，调用次数写明构成，到处是同一个数。

## 四、新的骨架

```
左栏                主区                                   右栏（四个标签，各管一件）
─────────────       ───────────────────────────────       ─────────────────────────
库架            →   所有库的卡片墙（留着，维护者 11-11 定）   进度      在跑 / 排队 / 下次定时 / 上一轮小结
和主 Agent 聊   →   一条对话：建库、改库、跨库的事          待确认  所有要你点头的卡，就地能点
我的库                                                     详情      选中的那一条：理由、核验记录、链接
  库 A  2       →   [库页头：名字 · 在追… · 立即运行]     文件      这个库在文件夹里怎么放
  库 B  ·           待看 · 资料库 · 问库 ｜ 来源与要求
＋ 新建库       →   一页：由主 Agent 生成 / 手动填写                 └ 高级（关卡 · 变更记录 · 文件夹）
套餐已用
设置            →   连接 · 外观与语言 · 库与用量 · 关于
```

和现在比：

- **库里 5 个标签 → 4 个。**「概览」没了：它的内容三去其二（四个数字、运行状态并到别处），剩下的「上一轮小结」和「最近收藏」正好是待看清空以后该看的东西，所以成了待看的空状态。进库永远落在待看。
- **库架留着。** 我原本建议去掉（左栏的库行已经有同样的信息），维护者 11-11 定了留着：仍是左栏第一项，只把卡上排队的说法和别处统一（P23）。打开流息仍直接落到上次那个库的待看。
- **「来源与要求」7 块 → 4 块 + 一行「高级设置」。** 页面从 2758 像素高降到 998（P14 画的是两个来源、展开着一个菜单的状态）。
- **对话框 9 个 → 4 个。** 跑一轮、放弃理由、核验记录、加来源、贴链接这五个不再弹窗；留下编辑、输入 API key、许可证、移除这个库。
- **向导没了。** 首次打开两步并成一屏，手动新建库四步并成一页（起步包留成来源那块的一行，按钮旁留「仅创建」）。
- **面上的概念 29 → 14。** 见 01 第三节。

数出来的结果（02 的十件事合计）：步数 44 → 32，点击 59 → 31，输入 14 → 10，决定 24 → 21，模型调用 29 → 26。

一个老实话：**每一页上「能点的东西」的个数没有明显变少**（按现状包第八节的数法：待看 27 → 同等状态下约 28，来源与要求 53–65 → 49，设置 41 → 43）。因为我把散在对话框和别的页面里的东西搬回了它该在的那一页。变少的是页面、对话框、概念、步数和重复，不是按钮总数。各张稿的个数在 `03-页面稿/clickable.json`。

## 六、设计语言：取了什么方法，没取什么

视觉不新造：沿用 维护者 11-10 定的「精密国际主义」（网格、无衬线、方角、靠字重和留白分层），稿子只画了浅色中文这一套，另外两套主题和英文字典照现有的换肤机制走。

这次取的是三个**做法**，不是哪个产品的样子：

- **收件箱式的逐条处理**（邮件客户端里「处理完就清空」的做法；RSS 阅读器 NetNewsWire、Reeder 的 源 → 列表 → 正文）：待看是一条条过、过完就空，空了就是「今天做完了」。所以待看是落地页，空状态是小结而不是一片白。
- **待办集中一处、就地处理**（Linear 的 Inbox / Triage 的做法）：所有要你点头的事在一个清单里，点一下就走，不用先跳到它「所在的地方」。
- **默认值 + 「高级设置」**（操作系统设置面板的做法）：面上是三档的「严格程度」，数字和提示词在「高级设置」里；会用的人一下就找得到，不会用的人永远不用看见。

明确没取的：仪表盘式的数字方块（概览那四个）、向导的步骤条、到处都有的数字角标、流水线节点图当主界面。这些是「看起来专业」的符号，不是这个产品每天要用的东西。

## 七、明确不做的

- **不动硬约束。** V1–V12 的行为、三种连接和说法、每条连接两个模型槽、中英两套字典、只有收藏 / 导入写头 / 编辑一条写 `notes/`、禁词与品牌词、API key 只进系统凭据保护、主 Agent 不经点头不能改东西、建议不放权、左栏放库、每轮上限按库、用量合计在设置、右栏四个标签、余额在左下角、Noto Sans SC——都原样。碰到的有两处，都是 维护者 定的：V6 原文里的「首页」两个字（概览没了，横幅放在库页顶上），列在 04 的第 1 题；「三套主题」改为丽芙模板的四套、默认研究对话，列在 04 的第 19、20 题。另外随包字体多了一款：研究对话的标题用 Noto Serif SC，随应用携带（04 的第 22 题）；界面字体仍是 Noto Sans SC。
- **不删后台能力。** 流水线、两道关卡、核验、改动来历的记录、排队、补跑都在；变的是它们出现在界面的哪一层。
- **不把主 Agent 和问库并成一个东西。** 两处都留着，只保证「在哪说都行」。并不并列在 04 第 12 题，我不推荐并。
- **不加「以后这类直接做」。** 规则卡自带动作不等于放权：每一张仍然要你点。
- **不做新来源类型、不做移动端、不改安装 / 更新 / 托盘 / 通知。**
- **不改视觉主题，不估工期，不改代码。**

## 八、措辞（维护者 11-11 追加）

维护者 试看稿子后说：「很多措辞都太口语化了，比如“谁定的”、“改一下”、“不要”等，指代非常模糊」，要改成大厂应用的行文方式。这和前面的诊断是一回事的另一面：口语说法省掉了对象（改什么？不要什么？谁定的什么？），用户得自己补全，所以读起来累。

做法（细则在 05）：按钮写动作本身（「提出修改」「拒绝」）；指代落到对象上（「暂停该来源」）；标题用名词短语（「操作来源」「推荐理由」）；状态用已 / 未 / 待 / 中（「运行中」「待评分」）；一个概念只用一个词（「跑一轮 / 这一轮 / 每轮」统一成「运行」，「打分 / 过关」统一成「评分 / 通过」）；人称能省则省。用户自己写的内容和模型回答的正文不改。

原先写进验收标准或 维护者 明定的四处说法，维护者 11-11 也逐题定了（04 第 13–16 题）：右栏「等你决定」改成「待确认」；五种抓取状态改成 正常 / 无更新 / 地址无效 / 暂时失败 / 访问被拒；问库的「库里没有。」改成「库内暂无相关内容。」；三种连接的名字不改。没有动的是产品里的专名（库、待看、资料库、问库、来源、主题、核验）。

## 九、给玄翎的几句

- 页面稿是线框级的：位置、层次、每个元素对应哪个功能编号是准的；字号、间距、颜色以现有主题为准，不用照稿子抠像素。
- 稿里的文案已按 05 的规范写过，可以直接进字典；进之前照旧过一遍禁词扫描。新旧对照和英文在 05 第二节。
- 有三处新能力要后台配合：N02「移入待看」、N07「重新评分」、N05 规则卡的动作表（哪类问题给哪几个动作）。其余都是界面层的搬动。
- O5（要重新载入才更新）和 O9（漏出原始报错）在新结构里位置变了，但毛病本身要单独修。
- 12 道题 维护者 11-11 都定了（见 04 开头）。第 1 题他选了 A：V6 原文的「首页横幅」要改成「库页顶上的横幅」——验收标准只有他能改，动 `standards.mjs` 前把改后的那一句给他看一眼。
