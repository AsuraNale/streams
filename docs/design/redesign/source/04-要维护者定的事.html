1. 库里还要不要「概览」这一页？

涉及：F13、F18、F19、F20、F21 · 碰硬约束：V6（原文「首页横幅说明」）

  • A（推荐）不要。 进库就是「待看」；待看清空以后，这一页显示上一轮的小结和最近收藏。连接出问题的横幅放在库页顶上，四个标签都看得见。
    代价：V6 的原文要你改一个词（「首页横幅」→「库页顶上的横幅」）；看惯四个数字方块的要改看一条漏斗；路由、测试、截图基线要重做。
  • B 留一个瘦的概览（只放上一轮小结 + 最近收藏），仍是第一个标签。
    代价：标签还是 5 个；待看空着时和概览显示的是同一批东西；横幅只在概览，停在别的标签时看不到。V6 不用改。

2. 「库架」这一页还要不要？

涉及：F12、F10

  • A（推荐）不要。 左栏的库行已经有名字、待看数、在跑 / 排队、有没有问题；打开流息直接落到上次那个库的待看。
    代价：你 11-05 认可的卡片墙作废；库多到十几个时左栏会变长（到那时再做筛选）；「在追什么」只在进了库以后的页头看得到。
  • B 留着，作为左栏第一项。
    代价：多一页要维护；它上面的每样信息左栏都有，等于又多一个「家」。

3. 提议卡和建议卡并成一种卡，流息发现的问题卡上直接带动作？

涉及：F16、F17、F59、N04、N05

  • A（推荐）并。 只有一种「要你点头的事」，小字写来处（主 Agent 提的 / 流息发现的）。规则卡自带动作（暂停这个来源 / 改地址 / 严格程度放宽一档 / 知道了），点一下由流息的代码做，不花模型调用；「让主 Agent 看看」是其中一个可选按钮。每一张仍然要你点了才动。
    代价：「建议卡」这个名字从界面上消失；四类问题各配哪几个动作要一张表，玄翎要写、你要过目；主 Agent 不再默认参与，它的「先查再答」只在你点了「让主 Agent 看看」时才有。
  • B 不并。 两种卡照旧，只是都列进右栏。
    代价：处理一张建议卡仍是 3 步、2 次模型调用、跨两个页面；用户还得分清两种卡。

4. 首次打开并成一屏，流息自己先选好连接？

涉及：F08、F09

  • A（推荐）并。 流息检测到已登录的连接，就先用推荐的那条，在最上面一行写明「用的是哪条、算在你的套餐里」，旁边「换一种连接」；同一屏直接问「想追踪什么」。三种连接和说法不变。
    代价：用户没有亲手选连接；连接是否真的通，要到发第一句话时才知道（不通就当场展开三种连接）；你 11-05 认可的两步形式作废。
  • B 保持两步。
    代价：建第一个库多 2 步、2 次点击、1 个决定、1 次模型调用。

5. 手动新建库从四步向导改成一页表单，起步包去掉？

涉及：F56、F57

  • A（推荐）改。 一页：名字、追什么（必填）、严格程度、来源（贴了就地试抓）、主题、放在哪、定时；「建库并跑第一轮」。13 步 19 次点击 → 6 步 6 次点击。
    代价：起步包「AI Agent 工具」（9 个来源）没有入口了（想留，可以在来源那块加一行「用现成的一套」）；没有「先不跑」的出口（想留，可以在按钮旁加「只建不跑」）。
  • A＋ 一页表单，但留起步包和「只建不跑」（维护者 选的这个）。 来源那块加一行「用现成的一套」，按钮旁加「只建不跑」。
    代价：页面上多两个能点的东西；「起步包」这个概念还在。
  • B 保留向导，只在最前面加一步「写要求」。
    代价：向导变五步，比现在还多一步；定时那一步仍然只能看不能改，除非另改。

6. 「现在跑一轮」点了就开始、不弹对话框；排队只在三处显示？

涉及：F22、F23

  • A（推荐）是。 按钮旁一行小字写「这一轮约 a–b 次调用」；点了就跑，别的库在跑就排队，按钮自己变成「在跑 · 停下」或「排队中 · 第 n 位」。排队只在页头按钮、左栏库行、右栏进度三处。每轮上限照旧兜底（V10 不变）。
    代价：开始前看不到那张「预计要做的事」清单（用哪条连接、每轮上限）；点错了要再点一下「停下」；你 11-10 说「开工」的排队形式（对话框提示 + 概览横幅）要改。
  • B 保留对话框，只去掉里面的「改上限」和排队时再弹的那个。
    代价：每次跑一轮多 1 次点击；两个库都跑仍要 6 次点击左右。

7. 放弃不强制写理由，「稍后」改成下一轮回来？

涉及：F26、F27、F32、N03、N04

  • A（推荐）是。 放弃立刻生效，随后一条小条让你点一个理由（营销稿 / 不相关 / 太浅 / 重复 / 写一句…），不点也行，可以撤销。同一个理由攒到 3 次，流息出一张卡问要不要写进要求。「稍后」的条目收进一行，下一轮回到待看。
    代价：理由会比现在少一些；方案里「放弃要写一句理由」作废；「去调提示词」的入口没了（提示词在高级里）。
  • B 放弃必须点一个理由（快选五个之一才算放弃）。
    代价：每次放弃固定 2 下；好处是每条都有理由。稍后的改法不受影响。

8. 关卡（提示词、过关线、核对单）收进「高级」，面上只留「严格程度」三档？

涉及：F51、F52、F53、F45、N01

  • A（推荐）是。 「来源与要求」上只有：要求一段话 + 严格程度（宽 · 中 · 严）。关卡的七个节点、提示词、过关线数字、核对单、试一条，都在「高级」里，功能不变。
    代价：想调提示词的人多点一下；三档对应的数字要定（我的建议：宽 0.4 / 0.5，中 0.5 / 0.6，严 0.7 / 0.7）；两条建库的路统一用「中」以后，手动建的库会比现在（0.7）放进来更多。
  • B 关卡留在「来源与要求」页面最下面，默认折叠，不加严格程度。
    代价：过关线仍然是要懂的数字；「连续 3 轮没有产出」时卡上给不出「放宽一档」这样的动作，只能让你自己去改数字。

9. 资料库只放已成文件的；「抓到的」搬到待看页，「待规范」变成一条提示？

涉及：F33、F39、N02、N07

  • A（推荐）是。 资料库 = 收藏的 + 我写的。没过关的在待看页底下（默认折叠），每条能「放进待看」；要求改过后可以重新打分。缺文件头的文件只在出现时，在资料库里提示一条。
    代价：习惯在资料库里找「抓到的」的要改地方；「放进待看」「重新打分」是两个新能力，要后台配合（都不写 notes/，V2 不碰）。
  • B 资料库保留四个视图。
    代价：「说能捞回却不能收藏」的问题还在，除非单独加按钮；「待规范」平时是 0 也占一个位置。

10. 「谁定的」改成一张改动记录；设置里的「主 Agent」一块和「定时一览」去掉？

涉及：F54、F64、F65

  • A（推荐）是。 每一步照样记谁定的，但不在每一块旁边标，集中成「高级 · 改动记录」。设置里去掉主 Agent 的会话轮数和缩写次数（程序内部状态）、去掉定时一览（右栏进度已经列了每个库的下次定时）；用量合计留在设置，并写明「各库 + 主 Agent」。
    代价：想知道某一项是谁定的，要进高级翻记录；设置里看不到主 Agent 的会话状态（可以放进「显示开发者信息」里）。
  • B 保留现状。
    代价：「来源与要求」每块多一个标记；设置多两块；同一个定时在三处显示。

11. 右栏：保持四个标签、各管一件，还是并成两个？

涉及：F58、F59、F60、F61

  • A（推荐）保持四个：进度 · 等你决定 · 详情 · 文件。我只重新分了工：每个标签只放别处没有的东西。不碰你 11-10 定的。
    代价：标签还是四个。
  • B 并成两个：「动态」（进度 + 等你决定）和「这一条」（详情 + 文件）。
    代价：碰你 11-10 定的「右栏四个标签」，要你改口；「等你决定」不再有自己的标签和数字，容易被进度盖住。

12. 「和主 Agent 聊」和各库的「问库」：保持两处，还是并成一处？

涉及：F14、F41、F44

  • A（推荐）保持两处，在哪说都行。 在库里的问库输入框说「想怎么改」照旧转给主 Agent；左栏的「和主 Agent 聊」用来建库和问跨库的事。
    代价：概念上还是两个入口；新用户仍可能问一句「该去哪说」（答案是：都行）。
  • B 并成一处：每个库一条对话，又问又改；左栏的「和主 Agent 聊」只留给建库。
    代价：动了你 11-05 反馈 #2、#3、#6 定下的形式；跨库的问题没有地方问；「只用库里的东西回答、每句带出处」（V9）和改库的闲聊混在一条对话里，出处的规矩更难守、更难验。

17. 人称：能省则省、避不开时用「你」，可以吗？

18. 「跑一轮」这一组词统一成「运行」，可以吗？

    代价：约 40 处要再换一遍；好处是验收标准里的词不用动。
